**Astro** — современный веб-фреймворк, который решает главную проблему современных сайтов: **избыток JavaScript**. Пока React-приложения заставляют браузер скачивать мегабайты кода, Astro по умолчанию отправляет **ноль JavaScript** — только HTML и CSS.

Это не оптимизация. Это **другая архитектура**.

## Что такое Astro

**Astro** — это фреймворк для **контентных сайтов**: блогов, лендингов, документации, интернет-магазинов и портфолио. Его главная особенность — **сервер-ориентированный подход**: HTML генерируется на сервере при сборке, а в браузер отправляется **готовый статичный результат**.

В отличие от Next.js или React-приложений, где весь сайт работает как **одно большое JavaScript-приложение** (SPA), Astro использует модель **многостраничного сайта (MPA)**. Каждая страница — это **отдельный HTML-документ**, как в традиционных сайтах на PHP или WordPress. Но при этом вы пишете на современном синтаксисе: HTML, CSS и JavaScript (или TypeScript).

## Zero JS by default — главная фишка

**Что это значит на практике:**

Когда вы создаёте страницу на Astro, весь код — компоненты, стили, логика — **выполняется на сервере** во время сборки. В браузер пользователя уходит **только HTML и CSS**. JavaScript — **ноль байт**, если вы сами не попросите обратного.

**Почему это важно:**

JavaScript — **самый тяжёлый ресурс** в вебе. Каждый килобайт JS нужно скачать, распарсить и выполнить. Пока браузер это делает — страница **не отвечает** на действия пользователя. Это называется **Time to Interactive (TTI)**.

Astro решает проблему **до её появления**: если на странице нет интерактива — нет и JS. Страница **интерактивна сразу**, как только загрузился HTML.

## Islands Architecture — как добавить интерактив

Полностью статичный сайт — это не всегда то, что нужно. Где-то **требуется интерактив**: корзина, поиск, слайдер, форма с валидацией.

Astro решает это через **Islands Architecture** (архитектуру островов).

**Идея простая:** представьте страницу как **океан статичного HTML**. В нём плавают **острова** — небольшие интерактивные компоненты. Каждый остров **гидратируется** (оживает) **независимо** от других, только когда это нужно.

**Как это работает в коде:**

Вы пишете компонент (на React, Vue, Svelte или чистом Astro) и добавляете **директиву** `client:*`:

```astro
---
import Counter from '../components/Counter.jsx';
---

<Counter client:visible />
```

**Что означают директивы:**

| Директива | Когда загружается JavaScript |
|---|---|
| `client:load` | Сразу при загрузке страницы |
| `client:idle` | Когда браузер свободен |
| `client:visible` | Когда компонент попадает в зону видимости |
| `client:media` | Когда срабатывает CSS media query |
| `client:only` | Пропускает серверный рендеринг, только браузер |

**Пример:** карусель с `client:visible` **не загрузит ни байта JS**, пока пользователь не доскроллит до неё. Остальная страница при этом **уже полностью интерактивна**.

**Ключевое отличие от React/Next.js:**

В React-приложении **вся страница** — это один большой JavaScript-компонент. Даже если 90% контента статичны, браузер **всё равно** скачивает React-рантайм, чтобы отрендерить их. Astro **гидратирует только то, что действительно нужно**.

**Можно смешивать фреймворки:** в одном проекте на Astro вы можете использовать **React, Vue, Svelte, Solid** — одновременно. Каждый компонент — это **отдельный остров**, и он работает независимо.

## Как выглядит код

Файл `.astro` имеет **две части**:

```astro
---
// Серверная часть — выполняется во время сборки
const title = "Мой блог";
const posts = [
  { id: 1, title: "Первая статья", description: "О чём-то интересном" },
  { id: 2, title: "Вторая статья", description: "О чём-то полезном" },
];
---

<!-- HTML-шаблон -->
<html>
  <head>
    <title>{title}</title>
  </head>
  <body>
    <h1>{title}</h1>
    {posts.map((post) => (
      <article>
        <h2>{post.title}</h2>
        <p>{post.description}</p>
      </article>
    ))}
  </body>
</html>
```

**Что важно:**

- **`---`** — серверный блок. Здесь вы пишете JavaScript/TypeScript: импортируете данные, обрабатываете их, готовите к выводу
- **Ниже** — HTML-шаблон. Он **статичен**, но может использовать **переменные** из серверного блока через `{...}`
- **Никакого клиентского JS** по умолчанию — только HTML и CSS

## Преимущества Astro

### 1. Скорость загрузки

HTML — **самый быстрый формат** для отображения контента. Нет JavaScript-рантайма, который нужно скачать и выполнить. Страница **появляется мгновенно** и сразу интерактивна.

### 2. SEO с первого дня

Поисковики видят **полный HTML-контент**. Не нужно ждать, пока JavaScript отрисует страницу. Google индексирует **весь текст, ссылки, изображения** сразу. Плюс — Core Web Vitals (LCP, INP, CLS) **автоматически хорошие**, а это **фактор ранжирования**.

### 3. Контент-коллекции

Astro имеет **встроенную систему** для работы с Markdown/MDX: Content Collections. Вы описываете схему данных через **Zod**, и Astro **проверяет** каждую статью на соответствие. Забыли `title` или `pubDate` — **ошибка на этапе сборки**, а не на продакшене.

### 4. Гибкость

Не нужно выбирать **один фреймворк**. Используйте React для сложного виджета, Svelte для лёгкого интерактива, а всё остальное пишите на чистом Astro. **Инкрементальная миграция** — можно переносить проект по частям.

### 5. Развёртывание где угодно

Astro работает с **любым хостингом**: Vercel, Cloudflare Pages, Netlify, AWS. Это **статический HTML** — его можно раздать с **CDN** по всему миру.

## Когда выбирать Astro

**Astro создан для:**

- **Блогов и медиа** — контент важнее интерактива
- **Лендингов** — быстрая загрузка = выше конверсия
- **Документации** — статичный контент, мгновенный поиск
- **Портфолио** — красиво, быстро, просто
- **Интернет-магазинов** — каталог и карточки товаров
- **Маркетинговых сайтов** — SEO и скорость критичны

## Когда НЕ стоит

- **Дашборды и админки** — много интерактива, SPA подходит лучше
- **Социальные сети** — реальное время, сложное состояние
- **Приложения с постоянным обменом данными** — чаты, трекеры

## Astro vs Tilda и WordPress

Если вы выбираете **между конструктором, CMS и фреймворком**:

| Критерий | Tilda | WordPress | Astro |
|---|---|---|---|
| **Порог входа** | Низкий | Средний | Средний |
| **Скорость** | Средняя | Зависит от темы | Очень высокая |
| **SEO** | Ограничено | Зависит от плагинов | Отличное |
| **Гибкость** | Низкая | Высокая | Максимальная |
| **Владение кодом** | Нет | Есть | Есть |
| **Цена** | Подписка | Хостинг + поддержка | Бесплатно |
| **Для кого** | Предприниматели | Блогеры, бизнес | Разработчики |

**Для блога и лендинга на Tilda** — быстрее и проще. **Для магазина на WordPress** — гибче. **Для высоконагруженного контентного сайта на Astro** — максимум скорости и SEO.

## Итог

**Astro — это фреймворк для тех, кто устал платить JavaScript за то, что можно сделать HTML.**

**Три ключевые идеи:**

1. **Zero JS by default** — ноль JavaScript, если он не нужен
2. **Islands Architecture** — интерактив только там, где он нужен
3. **Content-first** — создан для сайтов с контентом, а не приложений

**Что это даёт:** скорость, SEO, конверсия. **71% сайтов на Astro** проходят Core Web Vitals против **35% у Next.js**.

**Для кого это:** блогеры, разработчики контентных сайтов, те, кто ценит **простоту и производительность**.

Если вы хотите создать **быстрый сайт, который отлично ранжируется** — Astro стоит рассмотреть серьёзно.

## FAQ

### Astro заменяет React?

**Нет.** Astro **использует** React (или Vue, Svelte) для интерактивных компонентов. Но **страницы** рендерятся на сервере без React-рантайма. Это **не замена** — это **другая архитектура**, где React нужен только для островов.

### Нужно ли знать JavaScript для Astro?

**Базово — да.** Но порог **ниже**, чем у Next.js. В Astro вы пишете **больше HTML и CSS**, а JS — только когда нужно. Для блога достаточно **понимания основ**.

### Astro подходит для интернет-магазина?

**Да, для каталога.** Для лёгких магазинов (до 1000 товаров) Astro + готовые интеграции работают отлично. Для крупных проектов с личным кабинетом — **комбинация** Astro (фронт) + отдельный бэкенд.

### Можно ли использовать WordPress вместе с Astro?

**Да, часто используют headless-подход.** WordPress работает как CMS — вы пишете статьи в админке, а Astro подтягивает их через API и рендерит **статичные страницы**. Получается **скорость Astro + удобство WordPress**.

### Сколько учить Astro?

**Для базового сайта — 1–2 дня.** Синтаксис простой, документация отличная. Для продвинутых техник (Content Collections, интеграции) — **1–2 недели**. Это **быстрее**, чем Next.js.
