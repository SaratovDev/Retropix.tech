CSS к HTML можно подключить тремя способами. Но это не значит, что все три равнозначны. В **95% случаев** вы должны использовать только один — **внешний файл стилей**. Остальные два нужны в специфических ситуациях, и новичку важно понять разницу сразу, чтобы не набивать шишки на реальных проектах.

Разберём каждый способ, а потом — правила приоритета, которые объясняют, почему один стиль перекрывает другой.

## Способ 1: Внешний CSS-файл

Это стандарт индустрии. Вы создаёте отдельный файл с расширением `.css` и подключаете его в HTML через тег `<link>`.

```html
<head>
  <link rel="stylesheet" href="styles.css">
</head>
```

- **`rel="stylesheet"`** — говорит браузеру, что это таблица стилей.
- **`href`** — путь к файлу.

### Как писать путь (здесь 80% ошибок новичков)

| Расположение файлов | Что писать в `href` |
|---|---|
| HTML и CSS в одной папке | `href="styles.css"` |
| CSS в папке `css/` | `href="css/styles.css"` |
| HTML в папке `pages/`, CSS в `css/` на уровень выше | `href="../css/styles.css"` |

`../` означает «выйти на одну папку вверх». Если CSS не подключается — **первым делом проверьте путь**.

### Почему это лучший способ

- **Один файл управляет всем сайтом.** Поменяли цвет кнопки в одном месте — обновилось на всех 50 страницах.
- **Браузер кэширует файл.** При повторном заходе пользователя CSS загружается из кэша, а не с сервера. Сайт открывается быстрее.
- **Код чистый.** HTML отвечает за структуру, CSS — за внешний вид. Это разделение называется «separation of concerns» и это профессиональный подход.

## Способ 2: Внутренние стили

CSS пишется прямо в HTML-файле, внутри тега `<style>`, который находится в `<head>`.

```html
<head>
  <style>
    body {
      font-family: Arial, sans-serif;
      background: #f5f5f5;
    }
    h1 {
      color: #333;
    }
  </style>
</head>
```

### Когда это оправдано

- Вы работаете в **CMS или конструкторе**, где доступен только HTML-код страницы, а к файлам сайта доступа нет. Например, в Tilda вы можете вставить стили прямо в блок T123.
- Вы делаете **одностраничный прототип** и не хотите создавать отдельный файл.
- **Критический CSS** для первой отрисовки страницы — advanced-техника, для новичка не актуальна.

### Когда это плохо

- **Многостраничный сайт.** Каждую новую страницу придётся копировать стили заново. Изменили кнопку — правите в 20 местах.
- **Стили раздувают HTML-файл.** Браузер не кэширует их отдельно.

**Вывод:** знайте этот способ, но не используйте его как основной.

## Способ 3: Инлайновые стили

CSS пишется прямо в атрибуте `style` конкретного HTML-тега.

```html
<p style="color: purple; font-weight: bold;">Фиолетовый жирный текст</p>
```

У этого способа **самый высокий приоритет** — он перекрывает и внешние, и внутренние стили. Но это не преимущество, а проблема: вы не можете управлять такими стилями централизованно.

**Единственное реальное применение:** HTML-письма. Почтовые клиенты (Gmail, Outlook) плохо поддерживают внешние и внутренние стили, поэтому вёрстка email-рассылок делается инлайново.

**Для сайта — никогда.** Если вы ловите себя на мысли «быстренько поправлю стиль прямо в теге», остановитесь и откройте CSS-файл.

## Приоритет стилей: кто кого перекрывает

Когда на один элемент действуют несколько правил, браузер решает конфликт по такому порядку (от высшего к низшему):

1. **Инлайновые стили** (`style="..."`)
2. **Внутренние и внешние стили** — между ними побеждает тот, что написан **ниже в коде**
3. **Стили браузера по умолчанию**

Это и есть «каскад» — та самая **C** в названии CSS (Cascading Style Sheets).

**Практический пример:** если `<link>` стоит после `<style>`, внешние стили перекроют внутренние. Если наоборот — внутренние победят.

Понимание этого правила **экономит часы отладки**. Когда стиль «не применяется», в 90% случаев его перекрывает что-то более приоритетное.

## Чек-лист: почему CSS не подключается

Самые частые причины, по которым стили «не работают»:

- **Неправильный путь в `href`.** Проверьте регистр букв (на Linux-хостингах `Style.css` и `style.css` — разные файлы) и количество `../`.
- **Тег `<link>` не в `<head>`.** Перенесите его туда.
- **Забыли `rel="stylesheet"`.** Без этого браузер не поймёт, что за файл вы подключаете.
- **Опечатка в имени файла.** `style.css` vs `styles.css` — частая ошибка.
- **Кэш браузера.** Нажмите `Ctrl+F5` (Windows) или `Cmd+Shift+R` (Mac), чтобы сбросить кэш.
- **CSS-файл пустой или с синтаксической ошибкой.** Откройте его в браузере напрямую: `вашсайт.ру/css/styles.css`. Если видите код — файл на месте. Если 404 — путь неверный.

## Итог: что использовать

| Способ | Когда использовать | Приоритет |
|---|---|---|
| **Внешний файл** | Всегда для сайтов | Средний |
| **Внутренний `<style>`** | CMS, прототипы, критический CSS | Средний |
| **Инлайновый `style`** | Только email-рассылки | Высший |

**Правило для новичка:** создайте файл `style.css`, подключите его через `<link>` в `<head>`, и работайте только с ним. Этого достаточно для 99% задач.
