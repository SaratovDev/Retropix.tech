## Почему WooCommerce тормозит

**WooCommerce не «тормозит» сам по себе.** Проблема в том, что он **требует больше ресурсов**, чем обычный блог.

**Что нагружает сервер:**

- **Сессии и корзина** — данные хранятся в таблице `wc_sessions`, которая быстро растёт
- **AJAX-запросы** — каждая страница вызывает `admin-ajax.php` для обновления корзины
- **Запросы к `wp_postmeta`** — метаданные товаров и заказов хранятся там
- **Динамические страницы** — корзина, оформление, личный кабинет **не кэшируются**

**Вывод:** чтобы WooCommerce работал быстро, нужны **правильные настройки** и **достаточные ресурсы**.

## Способ 1. Кэширование страниц

**Page Cache** — **самый быстрый способ** ускорить магазин. Он сохраняет готовый HTML-код страниц и отдаёт его без обращения к PHP и базе данных .

**Что важно для WooCommerce:**

- **Кэшируйте** — главную, категории, страницы товаров
- **НЕ кэшируйте** — корзину, оформление заказа, личный кабинет. Это **динамические страницы**, они должны работать всегда «свежими»

**Популярные плагины:**

- **WP Rocket** — платный, но самый простой. Автоматически исключает WooCommerce-страницы из кэша
- **LiteSpeed Cache** — бесплатный, если ваш сервер на LiteSpeed. Работает на уровне сервера — быстрее
- **W3 Total Cache** — бесплатный, но требует настройки

**Таймаут кэша:** для магазина оптимально **12 часов** (43200 секунд). При изменении товара — кэш обновится автоматически.

## Способ 2. Объектный кэш (Redis)

**Object Cache** — сохраняет **результаты запросов к базе данных** в оперативной памяти. Вместо того чтобы каждый раз делать SQL-запрос, WordPress берёт данные из RAM.

**Для WooCommerce это критично** — потому что магазин делает **много одинаковых запросов** (например, категории товаров).

**Что нужно:**

- **Хостинг с поддержкой Redis** или **Memcached** (спросите у хостера)
- **Плагин:** Redis Object Cache или Object Cache Pro

**Реальные цифры:** магазины переходят с **4–5 секунд** на страницу товара до **менее 2 секунд** просто от включения объектного кэша.

## Способ 3. HPOS — новая система хранения заказов

**HPOS (High-Performance Order Storage)** — это **отдельная таблица для заказов**, вместо хранения в `wp_posts` и `wp_postmeta`.

**Что это даёт:**

- **Заказы загружаются на 30–50% быстрее**
- **Поиск по заказам ускоряется в 5+ раз**
- **Снижается нагрузка на `wp_postmeta`**

**Как включить:** WooCommerce → Настройки → Дополнительно → Функции → включить «High-Performance order storage».

## Способ 4. Отключение wc-cart-fragments

**`wc-cart-fragments`** — это AJAX-запрос, который **выполняется на каждой странице** для обновления иконки корзины. Он добавляет **500+ мс** к загрузке.

**Проблема:** на большинстве страниц (главная, блог, категории) **корзина не нужна**.

**Решение:** отключить, если у вас **стандартная корзина** без динамического обновления счётчика.

**Как:** добавьте в `functions.php`:

```php
add_action( 'wp_enqueue_scripts', function() {
    wp_dequeue_script( 'wc-cart-fragments' );
}, 20 );
```

**Что будет:** иконка корзины **перестанет обновляться в реальном времени**, но обновится при переходе на страницу корзины.

## Способ 5. Оптимизация изображений

**Изображения — главная причина медленной загрузки** магазина. Если у вас **50 товаров с фото по 3 МБ** — это **150 МБ** трафика на одного пользователя.

**Что делать:**

- **Сжимайте** все изображения перед загрузкой. Сервисы: TinyPNG, Squoosh
- **Используйте WebP** — на 25–35% легче JPEG
- **Правильные размеры** — не загружайте фото 3000px, если оно показывается в 400px
- **Lazy Loading** — работает из коробки с WooCommerce 10.6+ 

**Исключение:** **главное фото товара** на странице товара **не должно быть lazy** — оно должно загружаться сразу.

## Способ 6. Аудит плагинов

**Каждый плагин добавляет код, скрипты и запросы.** Если у вас **30 плагинов** — часть из них **точно лишние**.

**Что делать:**

- **Проверьте список.** Что можно удалить без потери функциональности?
- **Деактивируйте, а не удаляйте** сначала — проверьте, не сломается ли магазин
- **Замените тяжёлые плагины** на более лёгкие аналоги
- **Осторожно с page builders**: Elementor, WPBakery, Divi добавляют много кода

**Инструмент:** **Query Monitor** — покажет, какие плагины создают больше всего запросов.

## Способ 7. Оптимизация запросов к БД

**WooCommerce делает много запросов**, и некоторые могут быть **медленными**.

**Пример:** поиск купонов. Запрос с `LOWER()` **не использует индекс** и делает **полный скан таблицы**.

**Что делать:**

- **Уберите `LOWER()`** из запросов — MySQL и так **регистронезависимый**
- **Добавьте индексы** для часто используемых полей
- **Очищайте `wc_sessions`** — таблица может вырасти до **сотен тысяч строк** 

**SQL для очистки сессий:**

```sql
TRUNCATE TABLE wp_woocommerce_sessions;
```

**Осторожно:** это удалит **все корзины** активных пользователей.

## Способ 8. CDN для магазина

**CDN** раздаёт статику (изображения, CSS, JS) с **ближайшего к пользователю сервера** .

**Для магазина это критично** — если у вас покупатели **из разных регионов**.

**Что даёт:**

- **Быстрее загрузка** изображений
- **Снижение нагрузки** на сервер
- **Защита от DDoS**

**Рекомендация:** **Cloudflare** — бесплатный, простой, с хорошей интеграцией в WooCommerce.

## Способ 9. Современный хостинг

**Проблема может быть не в WooCommerce, а в хостинге.** Дешёвый shared-хостинг **не потянет** магазин .

**Что нужно:**

- **PHP 8.0+** — в 2–3 раза быстрее PHP 7.x
- **PHP-FPM + OPcache** — для оптимальной производительности
- **MySQL 5.7+ / MariaDB 10.3+** с InnoDB
- **Redis / Memcached** для объектного кэша
- **Достаточно CPU и RAM** (минимум 512 МБ для PHP)

**Если TTFB > 1 секунды** — проблема в хостинге. Переезд на **VPS** или **WooCommerce-оптимизированный хостинг** даст **заметный прирост**.

## Способ 10. Мониторинг и обслуживание

**Оптимизация — не разовое действие.** Магазин растёт, появляются новые товары и плагины.

**Что отслеживать:**

- **Core Web Vitals** в Google Search Console
- **Размер страницы** — в идеале **< 1.5 МБ**
- **TTFB** — цель **< 600 мс**
- **Размер `wc_sessions`** — если > 100 000 строк, пора чистить

**Регулярные задачи:**

- **Раз в месяц** — проверять скорость в PageSpeed Insights
- **Раз в квартал** — аудит плагинов, обновление зависимостей
- **Раз в год** — миграция на новый хостинг, если нужно

## Чек-лист: что сделать прямо сейчас

- [ ] Включить **HPOS** (с бэкапом!)

- [ ] Оптимизировать **изображения** (WebP, сжатие)

## Итог

**Скорость магазина на WooCommerce — это не одна «волшебная кнопка», а последовательность шагов:**

1. **Кэш + изображения** — 80% результата за 20% усилий
2. **Объектный кэш + HPOS** — следующий уровень
3. **Хостинг + CDN** — если база не помогает
4. **Мониторинг** — оптимизация не заканчивается

**Начните с первых двух пунктов** — уже через час магазин станет заметно быстрее. Остальное — по мере необходимости.

## FAQ

### Почему WooCommerce замедляет сайт?

**Сам по себе — не замедляет.** Проблема в том, что магазин **требует больше ресурсов**, чем обычный сайт. Если хостинг слабый — он не справится.

### Какой кэш-плагин лучше для WooCommerce?

**WP Rocket** — самый простой. **LiteSpeed Cache** — быстрее, если сервер на LiteSpeed. **W3 Total Cache** — бесплатный, но требует настройки .

### Нужен ли Redis для магазина?

**Да, если у вас больше 100 товаров** или **высокий трафик**. Redis **резко ускоряет** запросы к базе данных.

### Что такое HPOS и зачем он нужен?

**HPOS** — отдельная таблица для заказов вместо `wp_posts`. Заказы загружаются **на 30–50% быстрее**, поиск — **в 5+ раз**.

### Как часто чистить wc_sessions?

**Раз в месяц** или когда таблица превышает **100 000 строк**. Используйте `TRUNCATE TABLE wp_woocommerce_sessions`.
